Reading:
- The io-threads 10 loss is the IO thread the collector takes. With the same 10 IO threads, C with the
  collector thread is ahead of C default in all three cells: +4.3% at GET 512 B, +2.7% at SET 16 B, +14.6% at
  GET 64 B. Each gap is more than 10 task sd (11.9 sd at SET, 14.3 at 512 B, 37 at 64 B, using the larger sd).
- Going from io-threads 10 to 11 with the collector on adds about 10-11% in every cell, close to the 1/10 more
  IO threads.
- So the collector thread's cost is a thread, not a per-request cost. A doc comparison at an equal IO thread
  count (C-EP at io-threads N+1 against C default and stock at N) shows a gain in every tested cell; at an equal
  io-threads setting it shows a loss for GET 512 B and SET 16 B.
