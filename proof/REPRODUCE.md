## 2. Python model (3 minutes for 30 seeds, 6 minutes for 80)

Requires python3 (3.8+), standard library only.

    cd proof
    python3 model/lanes_model.py --seeds 30 | tee MODEL-RUN.log
    python3 model/lanes_model.py --seeds 80 | tee MODEL-RUN-seeds80.log

Expected last line: `RESULT: correct design clean, every broken variant detected`, the `correct` row with
`violating=0`, and every V1-V6 row with `violating>0`. Exit status 0. The scenario set is deterministic for
a given `--seeds` value (random.Random(seed) per scenario), so the counts in MODEL-RESULTS.md reproduce
exactly. The run used `taskset -c 12,13`; pinning does not change results.

## 3. TLA+ / TLC (2 minutes)

Requires Java 11+ and tla2tools.jar. The jar used was v1.7.4 from the official TLA+ GitHub release
(file `tla2tools.jar`, 2,274,532 bytes); download it with curl and run locally, nothing is sent anywhere.

    JAR=/some/dir/tla2tools.jar
    curl -sL -o "$JAR" https://github.com/tlaplus/tlaplus/releases/download/v1.7.4/tla2tools.jar
    cd proof/tla
    sh run_tlc.sh "$JAR" 0-1        # second argument: cores for taskset

The script regenerates the 10 `.cfg` files and the variant `.tla` copies from MC1.tla / MC2.tla, runs
TLC with `-workers 2 -deadlock` on each, and writes `tlc-<name>.log`. Expected: `MC1` and `MC2` print
"Model checking completed. No error has been found."; the eight `*V1_reverse`, `*V2_nobarrier`,
`*V5_splitseg`, `*V4_stale` configs print "Error: Invariant SerialEquivalent is violated." with a trace.
State counts as in MODEL-RESULTS.md section 2 (TLC's `-deadlock` flag only suppresses the deadlock report
at the terminal state; it does not affect invariant checking).

To check a single config by hand:

    java -cp "$JAR" tlc2.TLC -workers 2 -deadlock -config MC2.cfg MC2.tla
